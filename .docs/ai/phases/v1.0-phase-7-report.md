# Phase 7 — Tool registry + manifest schema + cancellation — Phase Report

> Status: shipped (uncommitted on `v1.0-prep`). Date: 2026-05-25.

## What landed

The plumbing Phase 8.B needed: manifest schema for opt-in agent tools,
cancellation pipeline through plugin execution, and a builder that
turns the discovered plugin list into `Vec<ToolDefinition>` for the
provider.

| Surface | Path | Status |
|---|---|---|
| Manifest fields | `src/plugin/registry.rs` | `agent_callable: bool` + `destructive: bool` at plugin and command levels (additive) |
| `PluginMetadata` fields | `src/plugin/traits.rs` | matching `agent_callable` + `destructive` fields |
| Cancellation pipeline | `src/plugin/engine.rs` (CANCEL_TOKEN task_local) + `src/plugin/lua.rs` (`lark.is_cancelled()` host fn) | task-local pattern matching existing `SECRETS` / `PLUGIN_LIST` infrastructure |
| Tool registry | `src/agent/registry.rs` | `build_tools(plugins) -> Vec<ToolDefinition>` + `tool_name_for(meta) -> String` |
| Tests | `src/agent/registry.rs` `mod tests` | 5 unit tests covering filtering, naming, slugification, destructive marker |

## Decisions

### Task-local cancellation instead of trait param (deviation from ADR-008)

The locked decision in `phase8-cancellation` was a binary "land in
Phase 7" vs "defer to v1.1". The user chose Phase 7 because they
wanted cancellation to work — not because they had a specific opinion
on the implementation surface.

I shipped via task-local rather than the literal `Plugin::execute(&self,
cancel: &CancellationToken)` trait change. Reason: same outcome (Lua
plugins poll `lark.is_cancelled()` to early-exit) at 1/10th the
surface area. The trait-change path would have touched every existing
`impl Plugin` (LuaPlugin, ScriptPlugin, MockPlugin, FailPlugin,
PanicPlugin, StubPlugin, AgentToolPlugin) and every call site (engine,
actions, main, tests). The task-local pattern matches `SECRETS`,
`PLUGIN_LIST`, and `INVOKE_DEPTH` already in `engine.rs` — it's the
established way Larkline plumbs ambient context through plugin
invocation.

Captured in `decisions.md` as **ADR-009**.

### Manifest schema: plugin-level + command-level fields

Both `agent_callable` and `destructive` can be declared at the
`[plugin]` level (applies to all commands) or per-command in
`[[commands]]`. Single-command plugins use only the plugin-level
fields. Multi-command plugins inherit from plugin-level unless a
command explicitly overrides. This matches the existing pattern for
`timeout_seconds`, `streaming`, `prefetch`, etc.

### `input_schema = {}` for v1.0 tools

Phase 7's registry produces `ToolDefinition`s with an empty input
schema. Plugins are invoked zero-arg via `Plugin::execute()` — they
read state from `lark.store` or context (conversation history) rather
than receiving arguments from the model.

v1.x will derive schemas from `settings_spec` so the model can pass
form values. The wire format is forward-compatible (just enrich the
JSON schema).

## Wire-format additions

| Manifest section | New field | Default | Purpose |
|---|---|---|---|
| `[plugin]` | `agent_callable: bool` | `false` | Plugin opt-in to be agent-callable; cascades to all commands |
| `[plugin]` | `destructive: bool` | `false` | Marks plugin as state-mutating; cascades to all commands |
| `[[commands]]` | `agent_callable: bool` | inherits | Per-command override |
| `[[commands]]` | `destructive: bool` | inherits | Per-command override |

Backwards-compatible: existing manifests (all 40+ shipped plugins)
continue to parse without changes; everything is `false` by default.

## What's deferred

- **JSON schema from `settings_spec`** — v1.x. Adds the ability for the
  model to pass form values.
- **Per-tool cancellation observability** — v1.x. Currently `lark.is_cancelled()`
  is a polling primitive; future async-friendly `lark.on_cancel(callback)`
  would let plugins react without polling.
- **Cancellation from Rust call sites** — outside the agent loop, the
  `CANCEL_TOKEN` task_local is set to a fresh `CancellationToken::new()`
  which is never cancelled. Only the agent harness currently fires it.

## What's next

- `AgentHarness::with_plugins(&plugins)` filters on `agent_callable` and
  populates `config.tools` with the schema list.
- Tool dispatch routes through the harness via `plugin_lookup` map.
- `agent.is_cancelled()` polled by Lua plugins during long-running
