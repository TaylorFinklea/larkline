# Phase 8 — Agent Loop — Smoke Runbook

> Manual end-to-end verification against ≥1 real provider before
> tagging Phase 8 ✅ in `current-state.md`.

## Prerequisites

- A working `lark ai-ask` smoke (Phase 6 runbook). If Phase 6 hasn't
  smoked, do that first — Phase 8 builds on the same provider stack.
- Configured `[ai]` section in `~/.config/larkline/config.toml` and
  a key for that provider.
- At least one agent-callable plugin discovered — for testing, set
  `agent_callable = true` on a safe read-only plugin (e.g. `weather`,
  `time`, or any `calendar` lookup). Don't test with destructive
  plugins until you've passed C.4.

## A — CLI without tools (3 minutes)

Sanity check: `agent-ask` works without any agent-callable plugins.

### A.1 — Help renders

```sh
lark agent-ask --help
```

**Expect:** usage with `--system / --model / --max-tokens / --yes` flags.

### A.2 — No-args is a usage error

```sh
lark agent-ask
echo $?
```

**Expect:** non-zero; `Error: Usage: lark agent-ask...` on stderr.

### A.3 — Happy path, no tools

With no `agent_callable = true` plugin in your config:

```sh
lark agent-ask "what does Larkline do, in 20 words"
```

**Expect:**
- Text streams to stdout as it arrives.
- Final newline.
- Stderr line: `[turns=1 tokens in=N out=M session=01...]`.

### A.4 — Session file created

```sh
ls "${XDG_STATE_HOME:-$HOME/.local/state}/larkline/sessions" | tail -3
```

**Expect:** A `*.jsonl` file matching the session UUID from A.3's
stderr footer.

Open it: should contain a `session` header line + `user` + `assistant`
+ `turn_end` entries.

### A.5 — Audit log captures spans

```sh
tail -10 "${XDG_STATE_HOME:-$HOME/.local/state}/larkline/agent-audit.log"
```

**Expect:** Four lines: `agent.turn` start, `ai.provider.request` start,
`ai.provider.request` end (with token counts), `agent.turn` end. All
share the same `trace_id`. No prompt text in the metadata.

## B — CLI with safe tools (5 minutes)

Enable a safe agent-callable plugin and verify the model can call it.

### B.1 — Opt a plugin in

Pick a safe (read-only) plugin manifest. Add to its `[plugin]`:

```toml
agent_callable = true
```

Verify discovery:

```sh
lark list --json | jq '.[] | select(.agent_callable) | .name'
```

**Expect:** the plugin name appears.

### B.2 — Agent uses the tool

```sh
lark agent-ask "use the <plugin name> tool and summarize what it returns"
```

**Expect:**
- Streaming text including phrases like "Let me check…" then the model
  actually calls the tool — you should see a `→ tool: <name>` marker
  on stdout.
- Final answer references something from the tool's output.
- Stderr footer: `[turns=1 tokens in=N out=M session=...]`. The `turns`
  count is 1 (the inner tool loop is *within* one turn — multiple turns
  are only from follow-ups).

### B.3 — Audit log captures tool call

```sh
tail -20 "${XDG_STATE_HOME:-$HOME/.local/state}/larkline/agent-audit.log"
```

**Expect:** Two `agent.tool_call` entries (start + end) interleaved
with the provider request spans. `parent_span_id` of the tool_call
matches the turn's `span_id`. End-record metadata: `tool`,
`duration_ms`, `status: "ok"`. No tool args in the metadata.

### B.4 — Session log captures tool_result

```sh
cat "${XDG_STATE_HOME:-$HOME/.local/state}/larkline/sessions/<session-uuid>.jsonl" | jq -c '.type'
```

**Expect:** Order something like `session, user, assistant, tool_result,
assistant, turn_end`. The `tool_result` entry has the plugin's output.

## C — Destructive tools + approval (3 minutes)

### C.1 — Mark a plugin destructive

In the manifest:

```toml
agent_callable = true
destructive = true
```

### C.2 — Default-block fires

```sh
lark agent-ask "use the <plugin name> tool now"
```

**Expect:**
- Streaming text where the model proposes the tool call.
- Then a "Tool plan rejected by hook" message in the conversation.
- The model usually responds verbally to the rejection and ends.
- Stderr footer: `stop_reason=hook_blocked` (or similar — check the
  session log's `turn_end` entry).

### C.3 — `--yes` bypasses the hook

```sh
lark agent-ask --yes "use the <plugin name> tool now"
```

**Expect:**
- The tool dispatches.
- Result feeds back; model responds with the result.
- Audit log shows `destructive: true` on the tool_call entry — the
  authoritative record that the user explicitly approved.

### C.4 — `--yes` is per-invocation, not sticky

Run `lark agent-ask` again (no `--yes`) immediately after. Destructive
tools should be blocked again — `--yes` doesn't persist.

## D — TUI plugin (3 minutes)

### D.1 — Plugin discovers as two commands

```sh
lark list | grep -i "ai " | head -3
```

**Expect:** Two lines: `AI Ask` and `AI Agent` (both under plugin
group "AI").

### D.2 — AI Agent form appears

Launch `lark`, search "AI Agent", press Enter.

**Expect:** Form with `Prompt` (required) + `System prompt (optional)`,
submit button labeled "Run agent".

### D.3 — Safe-tool path

Submit "use the <safe plugin> tool". (Same plugin opted-in from B.1.)

**Expect:**
- Spinner / loading state while the agent runs.
- Result row 1: prompt as label, full agent response as detail
  (rendered in preview pane), 🤖 icon, copyable.
- Result row 2: `Turns: 1 · Tokens: N in / M out`, with session ID +
  audit log path in detail. 📊 icon.

### D.4 — Destructive path is blocked

Submit "use the <destructive plugin> tool". The destructive plugin
should still be `agent_callable = true` + `destructive = true` from C.1.

**Expect:** The agent finishes verbally with a "tool plan rejected"
message. No state changes. (The TUI plugin doesn't pass `--yes` —
v1.0 safety stance is "destructive requires explicit CLI use".)

## Known gaps (deferred to v1.x)

- **No TUI approval modal.** TUI agent runs safe-only by default. CLI
  `--yes` is the explicit escape hatch.
- **No in-plugin streaming.** TUI plugin blocks for the full response;
  CLI streams.
- **No steering poll between chunks.** API + queue exist; mid-turn
  inject won't fire until 8.B's design extends.
- **No tree navigation.** Sessions are linear; `parent_id` field
  reserved for v1.1 `/fork` + `/clone`.

If any required check fails, file a v1.0 bug. Once pass, mark Phase 8 ✅
in `current-state.md` and proceed to Phase 9.
