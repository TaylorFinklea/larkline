## Deviations from the spec

None material.

Minor judgment calls:

1. **Atlassian `preview_full` setting type:** spec said "bool". The plugin
   manifest schema uses `type = "toggle"` (string-valued `"true"`/`"false"`)
   for boolean settings (matches `bitwarden/redact_secrets`,
   `github/include_drafts`, etc.). I used `toggle` for consistency with
   the existing pattern. The Lua side reads it via
   `lark.store.get("preview_full")` returning a string and treats
   `"true"`/`"1"` as truthy — exactly the parsing pattern the spec
   prescribed.

2. **ADF reducer placement:** spec said "extract the inline ADF reducer
   (currently `my-issues.lua:219-228`) as `adf_to_text(node)`". `lib.lua`
   already had a more elaborate `adf_to_plaintext` (used in the existing
   detail renderer). I added the simpler `adf_to_text` (matching the
   inline `flatten()` shape) as a SHARED helper alongside it, then
   copy-pasted into the four Jira files. Both reducers coexist; they
   serve different layers.

3. **Confluence storage-format quality:** the spec called this out as the
   one mid-implementation risk. Decision after writing the regex: ship
   it. Prose-heavy pages render cleanly; macro-heavy pages show some
   residual `[macro placeholder]`-ish text but never raw HTML. Documented
   the "best-effort" caveat in `docs/plugins/lark-nvim.md` and the
   `lark.nvim/README.md`. If Taylor's smoke test reveals quality is
   genuinely unusable, the fallback is to gate Confluence (not Jira)
   behind a separate setting in v0.14.x — see `next-steps.md`.

4. **Bitwarden helper extraction:** spec said "set `preview = render_detail(item)`
   reusing the existing detail renderer in `lib.lua`". `lib.lua` for
   bitwarden didn't actually expose a `render_detail`; the markdown body
   construction was inline inside `detail_output(item)` in `items.lua`.
   I extracted that block into a new `render_detail_markdown(item)`
   helper, with a 5KB cap, and made `detail_output` use it for `raw_text`.
   Equivalent semantics; cleaner factoring.

## Residual risks / follow-ups

1. **Confluence storage→text quality** — best-effort regex strip. May
   need to gate Confluence behind a separate toggle if Taylor's content
   is macro-heavy.
2. **Atlassian `preview_full=true` latency** — adds payload to every list
   call when on. Default off; documented tradeoff. If users complain, the
   long-term fix is Approach B (lazy fetch on row focus).
3. **5KB cap** — applied in plugin reducers, not in Rust. Plugins not
   covered by Phases C–E that opt into `preview` later need to do their
   own truncation.
4. **TUI ignores `preview`** — by design (spec constraint). If the field
   ever needs to render in the TUI, that's net new design work.
