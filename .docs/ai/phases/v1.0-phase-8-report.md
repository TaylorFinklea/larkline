## What works end-to-end

1. **Phase state machine.** `enum AgentPhase { Idle | Turn |
   AwaitingApproval | Retry }` with `require_phase()` gate at every
   public entry point. All four variants exist from day one for
   forward-compat.

2. **Turn snapshot.** Tools / model / system prompt frozen at turn
   start. Settings UI mutations apply on the *next* turn — no races
   with in-flight provider requests. Pinned by
   `snapshot_freezes_config_state` test.

3. **JSONL append-only session log** at
   `$XDG_STATE_HOME/larkline/sessions/<uuid>.jsonl`. UUID v7 IDs (time-ordered),
   tree-structured via `parent_id`, linear in v1.0 (tree traversal
   v1.1). Replay reconstructs `messages` on `reopen`. Crash recovery
   is free.

4. **Two-queue model.** `steer()` for mid-turn input (drained between
   provider calls; reserved for 8.B tool cycles); `follow_up()` for
   continuations (drained at turn boundary). `abort()` clears
   steering, preserves follow-up — per locked spec.

5. **Hook trait + DefaultApprovalHook.** `AgentHook::before_tool_call`
   returns `BlockDecision::Allow | Block(reason)`. Built-in
   `DefaultApprovalHook` blocks any plan containing a destructive
   tool. v1.1 will add plugin-registered hooks.

6. **Tool dispatch.** Inner loop iterates: provider call → if
   stop_reason=ToolUse, build plan → run hooks → dispatch → append
   tool_result → loop. Max 32 iterations to prevent runaway.
   Cancellation via task-local `CANCEL_TOKEN` polled by Lua.

7. **Safe-metadata audit log** at
   `$XDG_STATE_HOME/larkline/agent-audit.log`. Structured records:
   trace_id/span_id/parent_span_id, name, kind (start/end/event),
   metadata. Excludes prompts/completions/args/results/keys/headers by
   default. Test `unsafe_content_is_not_serialized` pins the schema.

8. **CLI + TUI plugin.** `lark agent-ask <PROMPT>` is the canonical
   entry point. `examples/plugins/ai/agent.lua` shells to it from the
   TUI. Multi-command manifest now exposes "AI Ask" + "AI Agent".

## v1.0 safety stance

The agent has a three-layer safety story:

1. **Manifest opt-in** — `agent_callable: bool` (default false). Plugins
   must explicitly opt in to be agent-visible.
2. **Per-command destructive flag** — `destructive: bool` (default false).
   Marks state-mutating commands; their tool definitions render with a
   `[destructive]` prefix in the description.
3. **Default-block on destructive plans** — `DefaultApprovalHook` blocks
   any plan containing a destructive call. CLI users can pass `--yes`
   to swap the hook for the no-op (allow-all). TUI users don't pass
   `--yes` — v1.0 ships without an approval modal, so destructive tools
   require the CLI path.

This is intentional. v1.0 ships **read/query agent operations through
the TUI** and **mutating agent operations through the CLI with
explicit `--yes`**. Phase 8.5 (v1.1) adds a modal approval surface for
the TUI path.

## What's deferred to v1.x

- **Approval modal in TUI** — `examples/plugins/ai/agent.lua` ships
  without it. Destructive tools blocked by default. CLI `--yes` is
  the explicit-opt-in escape hatch.
- **In-plugin streaming** — the TUI plugin blocks on `lark.exec_io`.
  The CLI streams to stdout. v1.1 adds an in-Lua streaming primitive.
- **Tree navigation / forks / clones** — sessions are linear in v1.0.
  Stored `parent_id` field is the forward-compat hook.
- **Context compaction** — long sessions exceed the context window and
  fail with a token-limit error. v1.1 adds pi-mono's compaction
  algorithm.
- **Plugin-registered hooks** — `AgentHook` trait is `pub` from day
  one; v1.1 adds `lark.register_agent_hook()` in Lua and the harness
  call sites that load them.
- **Content-capture opt-in for audit** — audit currently captures only
  safe metadata. v1.1 may add `[audit] capture_content = true` for
  power users.
- **Steering mid-turn** — queue + API exist; the actual poll between
  provider chunks lands when the inner loop has multi-call turns to
  make use of it (8.B has them, but the steering poll is still in a
  TODO comment because the cleanest insertion point depends on the
  final TUI hook channel design).
