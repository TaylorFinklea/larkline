# Smoke Runbook — v1.0 Phase 3 (Calendar v2 plugin)

> Internal phase gate. Not a public release tag — Phase 3 lives on
> `v1.0-prep`. Run this before merging Phase 4 (Mail plugin) to confirm
> the Calendar baseline is stable.

## Setup

```sh
cd ~/git/larkline
git checkout v1.0-prep
cargo build --release
cd macos-helper && swift build -c release && cd ..
# Put the helper on PATH for lark to find it (dev environment only —
# production users get it from Homebrew automatically).
export PATH="$PWD/macos-helper/.build/release:$PATH"
```

## Section A — Plugin invocation (no TUI)

```sh
./target/release/lark invoke "My Schedule" | python3 -m json.tool | head -50
./target/release/lark invoke "Today"       | python3 -m json.tool | head -30
./target/release/lark invoke "Tomorrow"    | python3 -m json.tool | head -30
```

Pass criteria for each:
- ☐ Returns valid JSON with `title`, `items` array
- ☐ Each event row has: `icon`, `label` ("HH:MM  <title>" or "all day  <title>"),
  `detail`, `preview` (markdown), `actions` array
- ☐ Day-header rows (only in My Schedule) have `icon: "─"`, no actions
- ☐ Events with a meeting URL show 3 actions: Join meeting / Open in
  Calendar.app / Copy meeting link
- ☐ Events without a meeting URL show 1 action: Open in Calendar.app
- ☐ ISO timestamps include local offset (e.g. `-05:00`), not `Z`

## Section B — TUI run

```sh
./target/release/lark
```

In the TUI, type `ca` (the calendar quickkey) → My Schedule loads.

Pass criteria:
- ☐ Day-header rows render as separators (icon `─`)
- ☐ Hover an event with a meeting URL → preview pane shows full markdown
  (Time, Location, Calendar, Meeting URL, Attendees, Notes)
- ☐ Press Enter on a meeting-event row → opens the meeting URL in the
  default browser / Teams / Zoom client
- ☐ Press `<C-a>` on an event row → action sub-picker lists all available
  actions
- ☐ Select "Open in Calendar.app" → Calendar.app opens to that event
- ☐ Press `y` on an event row → copies meetingURL (if present) or title

## Section C — Telescope (lark.nvim)

In nvim with lark.nvim loaded:

```
:Telescope lark
```

Pick "My Schedule" → results picker opens.

Pass criteria:
- ☐ Hover an event row → previewer pane (right side) renders the markdown
  body
- ☐ `<C-a>` opens action sub-picker
- ☐ `<CR>` on the row fires the primary action (Join meeting if URL,
  else Open in Calendar.app)

## Section D — Fallback path

Simulate the no-helper environment:

```sh
# Unset PATH override so larkline-macos-helper isn't found
PATH="$(echo $PATH | tr ':' '\n' | grep -v macos-helper | tr '\n' ':')" \
  ./target/release/lark invoke "My Schedule" \
  | python3 -m json.tool | head -20
```

Pass criteria:
- ☐ If icalbuddy is installed: returns 1 item with `icon: "📋"`, label
  "Calendar (icalbuddy fallback)", and the icalbuddy raw output in
  `preview`
- ☐ If icalbuddy is NOT installed: returns 1 error item with `icon: "!"`,
  label "Neither larkline-macos-helper nor icalbuddy installed", and
  `help_url` pointing at hasseg.org/icalBuddy/

## Section E — TCC denied path

Only verifiable if Calendar permission has not been granted to the
helper binary. Skip if you've already granted it.

```sh
# (Manually deny Calendar access for terminal/lark in System Settings →
# Privacy & Security → Calendars, then retry)
./target/release/lark invoke "My Schedule" | python3 -m json.tool
```

Pass criteria:
- ☐ Returns 1 error item with the message "calendar access denied — grant
  in System Settings → Privacy & Security → Calendars, then retry" and a
  `help_url` to the TCC settings (`x-apple.systempreferences:...`)

## If a scenario fails

File against `v1.0-prep`. Phase 3 sub-phases live in commits `f823065`
(exec_io), `70c405b` (lib.lua + schedule), `cec0b13` (today/tomorrow).
Most likely culprits by section:

- Section A fail → lib.lua's `helper_call` parser, helper response shape
- Section B fail (TUI) → schedule.lua's items[] structure, app.rs preview rendering
- Section C fail (Telescope) → lark.nvim previewer reading `entry.value.preview`
- Section D fail → has_helper PATH check, icalbuddy_fallback shell invocation
- Section E fail → error_item help_url not propagating to TUI status bar
