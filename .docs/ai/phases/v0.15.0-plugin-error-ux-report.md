## Decisions made during execution

### Refined Phase C scope

The original spec called for a `↻` row glyph, dedicated `?` key for help, and
lark.nvim keymaps. Discovery: `r` is already bound to `Action::RerunCommand`
and `o` to `Action::OpenUrl`. Cleanest design was to enrich those existing
handlers (RerunCommand checks retry_action first; OpenUrl prefers help_url)
rather than invent new keys. Status bar relabels conditionally. The row
glyph and lark.nvim keymaps are deferred — listed under roadmap **Next**.

### Refined Phase D scope

Plan called for `retry_action` + `from_exit` migration across 7 plugins. In
practice:

- **HTTP plugins** (GitHub, Atlassian, Linear) do not need `from_exit` —
  they have HTTP status codes in hand and route via dedicated translators
  (`github_http_error`, `atlassian.http_error_output`, `linear_http_error`).
- **Shell plugins** (Bitwarden, Docker, k8s, HA) include `from_exit`
  verbatim for forward compatibility, but it's dormant today: the host's
  shell-exec function returns stdout only; stderr is dropped. Plugins detect
  failure via empty stdout and route on that signal.
- **No plugin sets `retry_action`** in this release. Phase C's
  `RerunCommand` fallback (`r → engine.execute(plugin_index)` when
  retry_action is unset) covers every migrated plugin's top-level errors.
  Plugins with on_action chain handlers can opt in to `retry_action` later
  without a wire-format change.

This kept the migration narrow and reduced risk. Every error row gained a
`help_url`; the broader `retry_action` ergonomics ship when there's a real
caller for them (Bitwarden v2's chain flows being the most likely).

### `_shared/` directory convention

`examples/plugins/_shared/errors.lua` is a reference module — plugins copy
it inline because the sandbox has no `require`. To avoid `registry::scan`
treating `_shared/` as a malformed plugin, `scan` now skips any directory
whose basename starts with `_` or `.`. The same skip applies in
`tests/plugin_manifest_integration_test.rs`. Future shared modules can
land under the same convention.

### Status bar hints are conditional

`[r] retry` only renders when the focused row has `retry_action`. `[o] help`
only renders when the focused row has `help_url`. Normal rows show no
extra hints — the affordances stay invisible until they're real.

## Pre-tag gate (Taylor)

Per-plugin smoke test against a real `lark` binary + Telescope install:

1. Trigger a known failure (revoke token / break network / kill daemon) in each migrated plugin.
2. Confirm error row icon `!` and status bar shows `[o] help`.
3. Press `o` — verify the right docs URL opens.
4. Press `r` — verify the plugin re-runs (rerun fallback unchanged).
5. Confirm `[r] retry` is *not* shown (no plugin sets `retry_action` in v0.15.0).

Plugins to spot-check: GitHub, Atlassian, Bitwarden, Linear, Docker, k8s, HA.

When green:

```sh
bash scripts/release.sh set 0.14.0     # tag v0.14.0 first if not already
git -C ~/git/lark.nvim tag v0.14.0 && git -C ~/git/lark.nvim push --tags
bash scripts/release.sh set 0.15.0     # then v0.15.0
```
