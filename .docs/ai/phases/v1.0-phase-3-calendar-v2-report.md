## Wire format additions

`lark.exec_io(cmd, args?, opts?) -> { stdout, stderr, exit_code }`

| Field | Type | Meaning |
|---|---|---|
| stdout | string | captured stdout (UTF-8 lossy decode) |
| stderr | string | captured stderr (UTF-8 lossy decode) |
| exit_code | integer | process exit code, or -1 if killed by signal |

| opts field | Type | Meaning |
|---|---|---|
| stdin | string | piped to the subprocess's stdin |

Documented in `docs/LUA_PLUGINS.md`. Two new tokio tests in
`src/plugin/lua.rs` cover stdin round-trip and stderr+exit-code capture.
58 lib tests passing (was 55 before; +2 new + 1 existing exec test).

## Calendar plugin structure

Three plugin entry points, all sharing helpers via `-- SHARED:` markers
(canonical source in `lib.lua`):

- `schedule.lua` — 14-day timeline; events grouped by date with passive
  day-header rows ("Today · 2026-05-12", "Fri May 16 · 2026-05-16")
- `today.lua` — events for today only; no day headers
- `tomorrow.lua` — events for tomorrow only; no day headers

Each event row's OutputItem:
- `icon` — 📹 if meetingURL present, 📌 if allDay, 🗓 otherwise
- `label` — "HH:MM  <title>" (or "all day  <title>")
- `detail` — location, fallback to calendar title
- `preview` — markdown with **Time**, **Location**, **Calendar**,
  **Meeting**, attendee list with `*(you)*` marker + status, notes
- `copy_text` — meetingURL or title (for `y` quick-copy)
- `actions`:
  - Primary: "Join meeting" → `kind=open, args={meetingURL}` (when URL present)
  - "Open in Calendar.app" → `kind=open, args={"ical://event/<id>"}`
  - "Copy meeting link" → `kind=clipboard, args={meetingURL}` (when URL present)

## Decisions made during execution

### Local-timezone ISO from helper

Helper originally emitted UTC ISO strings (e.g. `2026-05-13T13:00:00Z`).
Set `ISO8601DateFormatter.timeZone = .current` in `Events.swift` so
emitted strings carry the user's local offset (e.g. `2026-05-13T08:00:00-05:00`).
Lua plugins now extract HH:MM directly without timezone math —
significantly simpler than the alternative (parse UTC, convert in Lua
via `date -j` per row).

### RSVP via Calendar.app, not helper

Phase 2.E discovery (EKParticipant.participantStatus is read-only) ripples
into Phase 3: the per-row "RSVP" action is the same as "Open in
Calendar.app" — `ical://event/<id>` opens the event view where the user
clicks accept/decline from the native UI. No separate RSVP action surfaced
in the row (would be a duplicate).

### Day headers as passive rows

Schedule.lua needed visual day separators across the 14-day window. Two
options considered:
- Day prefix on each row's label ("Tue May 13 · 9:00 Standup") — cluttered
- Passive header rows ("─ Today · 2026-05-12") interleaved with events — clean

Picked the latter. Passive rows have `actions = {}` and a `─` icon; the
TUI renders them as visually distinct dividers but they're still
selectable (harmless — pressing Enter on a divider falls through to
`copy_text` fallback or no-op).

### Snooze action deferred

The original Cal v2 spec listed "Snooze 5/10 minutes" as a secondary
action. Snooze requires either:
- Action chain that re-fetches events with a future start_iso (cosmetic
  only — doesn't actually delay anything)
- Setting an EKReminder via EventKit (different framework, scope creep)

Decision: skip for v1.0. The action label was misleading anyway —
"snooze" implies notification suppression which is outside the helper's
EventKit scope. If a beta tester requests it, revisit in v1.1 as either
an EKReminder integration or a no-op cosmetic gesture.

### lib.lua canonical source, inlined per plugin

mlua sandbox has no `require()`. Each plugin file inlines the helpers
it needs with `-- SHARED:` markers. `lib.lua` is the canonical source
of truth — diff'ing across the four files surfaces drift trivially.
Same pattern as existing plugins (github, atlassian, ccusage).
