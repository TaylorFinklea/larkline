## CLI design

The CLI is intentionally minimal — flags map 1:1 to `AskRequest`:

```sh
lark ai-ask [--system TEXT] [--model ID] [--max-tokens N] <PROMPT...>
```

Streams `ProviderEvent::TextDelta` to stdout as plain text (no envelope).
Token usage + stop reason land on stderr after the stream closes.
Non-zero exit on provider errors. Mirrors pi-mono's `pi -p "..."`
non-interactive mode, which is the right primitive for scripting and
for the plugin to shell into.

**Why CLI-first:** the plugin couldn't be streaming-capable in Phase 6
(Lua plugins don't have a streaming output primitive — that's Phase
6.5). Shipping the CLI gives streaming UX *somewhere* on day one and
lets advanced users + scripts skip the TUI entirely.

## Plugin design

Two fields, one icon, one shell-out:

```
[Prompt:    ___________________________ ] (required)
[System:    ___________________________ ] (optional, blank = provider default)
                                  [ Ask ]
```

On submit: `lark.exec_io(LARK_BINARY, {"ai-ask", "--system", S, prompt})`.
Blocks for the full response (Phase 6.5 makes this streaming).

Result rendering:
- Row 1: prompt as label, response in preview pane, copyable.
- Row 2 (if usage reported): `Tokens: N in / M out` summary.
- Error path: ❌ icon, friendly label for common cases (missing key,
  rate limit), `help_url` → `docs/AI_INTEGRATION.md`.

Followed the v0.15.0 `error_item` pattern with inlined helper (the lark
sandbox has no `require`). Marked `-- SHARED:` for diff-able divergence.

## Decisions

| Decision | Rationale |
|---|---|
| **Plugin shells out to CLI; no `lark.ai_ask` host fn** | One code path for keys/streaming. In-process host fn defers to Phase 8 when the agent loop needs fine-grained event control. See ADR-008. |
| **No model/max-tokens fields in the form** | Advanced users can drop to `lark ai-ask --model X --max-tokens N` directly. Keeps the form one-screen and low-friction. |
| **System prompt default = empty (= provider default)** | Less opinionated; the user owns their persona. |
| **Token usage as a secondary row, not footer** | Successful runs are visibly accounted for without taking screen space from the answer. Skipped silently when not reported (Ollama). |
| **Help URL → `docs/AI_INTEGRATION.md` on the canonical repo** | Single source of truth; survives plugin distribution. |

## What's deferred to Phase 6.5

- **In-plugin streaming.** Today the plugin blocks. Needs a new Lua
  host fn `lark.ai_ask(prompt, on_delta_fn)` that pumps deltas through
  a Lua callback. Will live alongside the existing `lark.exec_io`
  pattern.
- **Per-`EngineEvent::PartialOutput` kind tagging** — distinguish
  `text_delta` / `thinking_delta` / `tool_call_delta`. Future-proofs
  for Phase 8.E. Pi-mono pattern.

## What's deferred to v1.x

- **Chained re-ask action.** Each invocation re-shows the form. A
  "Re-ask" action on the result row that chains back to the form is
  nice but adds complexity.
- **Save-to-history.** No persistent record of past prompts in the TUI
  (the CLI doesn't have one either). Sessions land in Phase 8.E.
