# Smoke Runbook — v1.0 Phase 4 (Mail plugin)

> Internal phase gate. Not a public release tag — Phase 4 lives on
> `v1.0-prep`. Mail's mutating actions touch real email; agent could
> not verify them end-to-end. This runbook is your test list.

## Setup

```sh
cd ~/git/larkline
git checkout v1.0-prep
cargo build --release
# Symlink the mail plugin into the user plugin dir (one-time):
ln -sf "$PWD/examples/plugins/mail" ~/.config/larkline/plugins/mail
ls -la ~/.config/larkline/plugins/mail   # confirm symlink
```

TCC permission for AppleScript-to-Mail.app is already granted on your
machine (verified during the helper probe). If you ever revoke and
re-grant: System Settings → Privacy & Security → Automation → Terminal /
lark → Mail.

## Section A — Read-only commands (low risk)

Each of these is read-only — no mutations to your inbox.

### A1. Inbox

```sh
./target/release/lark invoke "Inbox" | python3 -m json.tool | head -40
```

Pass criteria:
- ☐ Returns 12-30 messages (per-account cap × enabled accounts)
- ☐ Each row has icon (📨 unread / 📧 read / 🚩 flagged), subject as label,
  sender + "Xh ago" / "Xd ago" as detail
- ☐ Each row's `preview` contains markdown with **From**, **Account**,
  **Date**, message body
- ☐ Each row has 1 action: "Open in Mail.app" with `command: "open"`
  and `args: ["message:..."]` containing the URL-encoded Message-ID
- ☐ First call may take 10-15s if Mail.app cold-caches; subsequent ~3s

### A2. Mail Search

```sh
# In TUI, hit Cmd-K / `:` to open the search bar and type "ms" (quickkey).
# Or:
./target/release/lark
# then type the search filter to find "Mail Search", press Enter.
# A form prompts for "Search query (subject + sender)".
# Enter a word you know is in some message subject (e.g. "github").
```

Pass criteria:
- ☐ Form prompts for query
- ☐ Submitting returns matched messages (newest-first) with the same
  row shape as Inbox
- ☐ "No matches" row when query returns 0 results

### A3. Open in Mail.app (action verification)

In TUI: invoke Inbox → hover any row → press Enter.

Pass criteria:
- ☐ Mail.app comes to foreground (if not already)
- ☐ The selected message is highlighted in Mail.app's main window
- ☐ No error flash in lark's status bar

## Section B — Triage mutating actions (test on safe messages)

⚠️ **Test on a low-stakes message** — pick a marketing email, a Daily
Digest, or a notification you don't care about. Each action below
mutates real state in your INBOX.

Setup: invoke Triage in TUI: `lark` → "Triage" → Enter.

### B1. Mark read / Mark unread

Pick an unread (📨) message. Action sub-picker via `<C-a>` (or `?` in
some keymaps).

- ☐ See "Mark read" action available
- ☐ Press Enter on "Mark read" → action fires (brief flash, may be empty)
- ☐ Check Mail.app: message is now read (no bullet next to it)
- ☐ Re-invoke Triage: same message now shows 📧 icon and "Mark unread"
  in actions (auto-toggles)
- ☐ Press "Mark unread" → reverses

### B2. Flag / Unflag

Pick any message (read or unread, doesn't matter).

- ☐ Action sub-picker shows "Flag" (or "Unflag" if currently flagged)
- ☐ Press Enter on Flag → message gets the 🚩 flag in Mail.app
- ☐ Re-invoke Triage → row icon is now 🚩; action label is "Unflag"

### B3. Archive

Pick a low-stakes message.

- ☐ Action sub-picker shows "Archive"
- ☐ Press Enter → message is moved out of INBOX (to Archive on iCloud,
  to All Mail on Gmail)
- ☐ Re-invoke Triage → message no longer appears

### B4. Delete (confirm flow)

Pick a marketing email you'd actually delete.

- ☐ Action sub-picker shows "Delete"
- ☐ Press Enter → lark prompts for confirmation (the `confirm=true`
  flag on the action triggers this)
- ☐ Confirm → message moves to Trash in Mail.app
- ☐ Re-invoke Triage → message no longer appears
- ☐ Verify in Mail.app: open Trash, message is there (recoverable)

### B5. Reply

Pick a message you'd reply to.

- ☐ Action sub-picker shows "Reply"
- ☐ Press Enter → Mail.app opens a reply composer with the message
  quoted in the body
- ☐ Close the composer without sending

### B6. Forward

Same as Reply but with "Forward".

- ☐ Action sub-picker shows "Forward"
- ☐ Press Enter → Mail.app opens a forward composer with the message
  contents
- ☐ Close without sending

## Section C — New Mail (compose flow)

In TUI: `lark` → "New Mail" → Enter.

- ☐ Form prompts for To (recipient address) and Subject
- ☐ Enter your own email address as To and "[larkline test] safe to delete"
  as Subject
- ☐ Submit form → lark shows a row "Open Mail.app composer to your-email"
  with preview describing the action
- ☐ Press Enter on the "Open composer in Mail.app" action → confirm
  prompt fires (`confirm=true` on the action)
- ☐ Confirm → Mail.app composer window appears in foreground with To
  and Subject pre-filled, body empty
- ☐ Type a test body, click Send → message arrives in your own inbox
- ☐ The "Copy mailto: URL" secondary action: press Enter on that
  instead → clipboard has `mailto:<email>?subject=<subject>`

## Section D — Telescope (lark.nvim)

In nvim with lark.nvim loaded:

```
:Telescope lark
```

Pick "Inbox" or "Triage" → results picker opens.

- ☐ Hover any row → previewer pane (right side) renders the message
  body as markdown (from Phase v0.14.0 + the per-row `preview` field
  set by the plugin)
- ☐ `<C-a>` opens the action sub-picker for the focused row
- ☐ `<CR>` fires the primary action (Open in Mail.app)

## Section E — Failure paths

### E1. TCC permission denied

If you revoke AppleScript-to-Mail permission and re-invoke Inbox:

- ☐ Returns 1 error row with `icon: "!"`, label includes "Mail error:"
  and stderr text from osascript, plus a `help_url` pointing at
  `x-apple.systempreferences:com.apple.preference.security?Privacy_AppleEvents`
- ☐ Pressing `o` on the error row opens System Settings

### E2. Mail.app not running

Mail.app launches on the first osascript call. If it crashes mid-query:

- ☐ Plugin returns an error row with osascript's stderr
- ☐ Pressing `r` re-runs the plugin (existing v0.15.0 retry behavior)

## If a scenario fails

File against `v1.0-prep`. Phase 4 lives in commits:
- `4f8ea5f` — 4.A/B: scaffolding + Inbox
- `8877888` — 4.C/D/F: Search + Triage + New Mail

Most likely culprits by section:
- A1 fail → inbox.lua's JXA query or lib.lua's format_message_row
- A2 fail → search.lua's form schema or the build_search_jxa function
- A3 fail → urlencode percent-encoding, or message: URL scheme not
  registered with Mail.app on your system
- B1-B6 fail → triage.lua's mutation_action JXA scoping
  (whose({messageId: ...}) might be slow or miss the message)
- B4 confirm fail → ItemAction.confirm field not propagating to the
  dispatcher
- C fail → compose.lua's build_compose_jxa or Mail.OutgoingMessage API
- D fail → cross-cuts v0.14.0 Telescope previewer; verify the row's
  `preview` field is non-empty in the JSON
