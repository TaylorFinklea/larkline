# Phase Report: v1.0 Phase 4.5 — Mail UX polish, TUI per-row actions, mobile layout

> 2026-05-17 · branch `v1.0-prep` (larkline) · 10 commits

## Outcome

Phase 4.5 is an unplanned interstitial between Phase 4 (Mail plugin
read/search/triage/compose) and Phase 5 (AI Provider trait). It bundles
the polish work that surfaced once Taylor began dogfooding the Mail
plugin end-to-end. Three threads landed in parallel:

1. **Mail UX** — viewable HTML body rendering (w3m / pandoc), inline
   image preview via chafa, perf fix that took Inbox listing from a
   30s timeout to ~7s, plus a clutch of smaller chain-action bugs.
2. **TUI per-row actions** — Space power menu now surfaces the focused
   row's plugin-provided actions as a "This item" category with digit
   shortcuts; status bar advertises this via an `[SPC] actions` hint
   when applicable.
3. **Responsive layout** — width-based profiles (Phone / Narrow /
   Medium / Wide) so Larkline degrades gracefully on phone tmux
   sessions instead of cramming 6 widget cards into 80 cols.

No host-side wire-format changes. One new `lark.*` host fn
(`lark.plugin_dir`). One new Lua TUI feature (`:layout <profile>`
override command).

Phase 5 remains the next milestone; this work was purely reactive to
smoke-test findings.

## Thread 1 — Mail UX

### Triage merge (`8163196`)

Taylor's first dogfood reaction: "why is Triage separate from Inbox?"
Triage duplicated every Inbox row with an extra action set. Merged
Triage's mutating actions (Mark read/unread, Flag, Archive, Delete,
Reply, Forward) directly onto Inbox rows; dropped the standalone
Triage command from the manifest. One read-only Inbox command now
carries the full action set per row.

### View body chain action (`c33e110`, `b830b12`, `7de4985`)

Inbox rows now have a "View body" action that drills into a fullscreen
markdown render of the message body. Three iterations:

1. **`c33e110`** — initial: passed body/subject/sender as separate
   chain args, on_action received them as table indices. Broken
   because `crate::actions::execute_chain` joins `args[1..]` with
   spaces into a *single* context string.
2. **`b830b12`** — fix: pack the three fields as JSON, decode in
   on_action. Live verification: `lark action Inbox --action-json
   <view-body>` returned the body text correctly.
3. **`7de4985`** — perf fix discovered at the same time: the inbox
   listing JXA was reading `m.content()` (the slowest single op in
   Mail.app scripting) for every one of 30 messages. Inboxes routinely
   timed out at 30s. Moved body-fetching to on-demand in the
   View body chain handler via a single-message `whose({messageId})`
   lookup. Listing time dropped to ~7s; View body fetch is ~0.5-1s.

### Rich HTML rendering (`a999041`)

`m.content()` returns Mail.app's already-stripped plain-text alternative
— missing links, replacing images with `￼` (object replacement
char). For real HTML rendering we need the raw RFC822, parsed and
rendered properly. Chain:

1. Fetch `m.source()` (RFC822) via JXA.
2. New Python helper `examples/plugins/mail/mail_render.py` extracts
   the `text/html` alternative via Python stdlib `email` module.
3. Render HTML through the first available of:
   - `w3m -dump -T text/html` (preferred — purpose-built for terminal
     HTML, un-nests marketing-mail layout tables)
   - `pandoc -f html -t plain --reference-links` (clean for
     correspondence; noisier on heavily-styled marketing mail)
   - `lynx -dump -force_html` (fallback)
   - `text/plain` MIME alternative (fallback)
   - `m.content()` (last resort)

Result wrapped in a markdown code fence so lark's themed markdown
renderer preserves spacing. Invisible Unicode preheader filler
(U+034F, U+00AD, ZWNJ family, U+2800 braille blank, U+FEFF BOM)
stripped before rendering. Footer line names the renderer used
(`_rendered via w3m_`) for diagnostic transparency.

### View images chain action (`a999041`, `6450ea0`)

Separate chain action that drops into a fullscreen ANSI rendering
of the email's images. Implementation:

- `mail_render.py --save-images DIR` saves embedded `image/*` MIME
  parts AND parses the HTML for remote `<img src="https://...">`,
  downloading those too (4MB cap per image, 8s timeout, 25-image
  cap, 1KB minimum to skip tracking pixels).
- `chafa --format=symbols --size=80x24 --animate=off` renders each
  image to ANSI symbol blocks.
- Output returned as `raw_text` WITHOUT `output_format = markdown`
  so the ANSI escapes pass through `ansi_to_tui` into ratatui as
  styled spans (the markdown renderer would eat the escapes).
- Falls back to a plain attachment listing when chafa isn't
  installed.

`6450ea0` fixed a separate issue where chafa was emitting OSC 10/11
(foreground/background color queries) to `/dev/tty` even with stdout
piped. The terminal echoed responses back into lark's stdin and
those bytes appeared in the search field. Flags `--probe=off
--polite=on --relative=off` silence the probing.

### Bitwarden Generate "Generate another" (`7de4985`)

Hard-coded to 20 chars + standard charset, ignoring whatever the user
configured in the form. Pack the bw args used into the chain context;
on_action decodes and re-runs. Same pattern as View body's JSON arg
packing. Detail line now reflects the real options used.

## Thread 2 — TUI per-row actions

### Action palette navigation fix (`eae7532`)

User-reported bug: in Mail Triage (later Inbox), pressing j/k inside
the action palette navigated the rows behind the palette instead of
the action items. Missing `Action::MoveUp` / `Action::MoveDown`
branches for the palette state. Added with a regression test.

### Power menu "This item" category (`8e48396`)

Per Taylor's direct request: "action palette should be baked into the
Space command, with the context of the currently highlighted item."
When the user presses Space in ViewOutput mode, the power menu now
prepends a "This item" category listing the focused row's actions
with digit shortcuts (1-9, then a-z for overflow). New `Action`
variant: `RunFocusedItemAt(usize)`. Two new regression tests cover
the menu construction and the run-at-index dispatch.

The standalone `:` action palette stays available; the power menu
integration is additive.

### `[SPC] actions` hint (`f6dde38`)

Status bar advertises the new shortcut: when the focused row has more
than one action, the hint reads `[SPC] actions`; with zero or one,
falls back to `[SPC] menu`. Helps new users discover the per-row
action shortcut.

## Thread 3 — Responsive layout

### `LayoutProfile` (`7ba697e`)

New module `src/tui/profile.rs` with four width regimes:

| Width | Profile | Widgets | Right pane | Status hints |
|---|---|---|---|---|
| < 60 | Phone | 0 | no | 3 |
| 60-99 | Narrow | 0 | no | 5 |
| 100-159 | Medium | 4 | yes | all |
| >= 160 | Wide | 6 | yes | all |

Profile is derived per-frame from `frame.area().width`. Each render
function consults it to gate decorations the terminal can't fit. The
profile is a hint, not a constraint — explicit user state flags
(`widgets_visible`, `sidebar_hidden`) still win. The profile only
adds width-based vetoes so narrow terminals don't pack 6 cards into
80 cols or render a side-by-side split that crushes both panes.

`:layout phone|narrow|medium|wide|auto` command sets a manual
override (useful when a terminal misreports width over mosh / nested
tmux / phone tmux). `:layout auto` clears the override.

Mobile target: Taylor's phone tmux session was unusable due to
horizontal cramming. With Phone profile auto-detected at < 60 cols,
the UI reduces to: single-column list + abbreviated status hints.

Same change also fixed a dispatch bug where `ViewOutput` mode without
the right pane fell through to `render_unified_list` instead of
`render_output_pane`. Now narrow ViewOutput renders full-width
output as expected.

## Wire-format additions

None at the OutputItem level. Two additions at the Lua host API:

- **`lark.plugin_dir`** (string) — absolute path to the plugin's
  source directory. Lets a plugin invoke sibling helper scripts;
  the mail plugin uses this to find `mail_render.py`. Implementation
  in `src/plugin/lua.rs` `register_api` (now takes `&Path`).
- **`AppState.layout_profile_override`** (`Option<LayoutProfile>`) —
  set by `:layout <profile>`; consulted by `render()` before falling
  back to width-derived profile. Cleared by `:layout auto`.
