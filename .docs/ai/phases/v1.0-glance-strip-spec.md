# Glance Strip — spec

> Status: approved 2026-05-29. A compact 1-line strip of at-a-glance metric
> chips, lighter than the 6-line widget row. Example: caffeinate minutes left.

## Decisions (locked with Taylor)

1. **Placement** — a dedicated 1-line strip between the content area and the
   bottom status bar (height 0 when empty).
2. **Data source** — reuse the widget refresh/prefetch/cache; render a compact
   chip from the plugin's output. Plugin sets `output.status` (short string);
   falls back to a truncated `title`.
3. **Management** — reuse the widget pin system (Plugin Manager + `A` picker,
   `plugin-manager.json`), with a separate `disabled_status` opt-out list.
4. **Interactivity** — selectable: focus the strip, ←/→ between chips, Enter
   opens the focused plugin (mirrors widget-card open).

Internal name: **glance strip** (`glance_*` / `status_*` in code) to avoid
colliding with the existing bottom `status_bar`. Manifest flag: `status`.

## New surface (spec-derived — implement exactly)

- **Manifest** (`ManifestPlugin` + `ManifestCommand`, `src/plugin/registry.rs`):
  - `status: Option<bool>` — opt in. Per-command falls back to plugin-level,
    mirroring `agent_callable`.
  - `status_refresh_secs: Option<u64>` — per-command falls back to
    plugin-level, then to `widget_refresh_secs`, then default 30.
- **`PluginMetadata`** (`src/plugin/traits.rs`): `status: bool`,
  `status_refresh_secs: u64`.
- **`PluginOutput`** (`src/plugin/traits.rs`): `status: Option<String>`
  (`#[serde(default)]`). The compact chip text; when `None`, the strip uses a
  char-truncated `title`.
- **`PluginManagerConfig`** (`src/config.rs`): `disabled_status: Vec<String>`
  (`#[serde(default)]`) + `is_status_disabled(group, name)` + a toggle, mirror
  of `disabled_widgets`.
- **`AppState`** (`src/app.rs`): `status_indices: Vec<usize>`,
  `status_visible: bool`, `status_focused: bool`, `status_selected: usize`.
- **Actions** (`src/action.rs`): `StatusItemOpen` (open focused chip's plugin),
  reuse MoveLeft/Right + MoveUp/Down for focus/nav as widgets do.

## Implementation (codebase-derived — mirror the named pattern)

1. **Parse + inheritance** — in `parse_manifest`, set `status` /
   `status_refresh_secs` on `PluginMetadata` exactly like `agent_callable` /
   `widget_refresh_secs` (single + multi-command, with the fallback chain
   above). Update every `PluginMetadata` literal (registry + test stubs in
   `agent/registry.rs`, `plugin/mod.rs`, `agent/harness.rs`) with
   `status: false, status_refresh_secs: 0`.
2. **Indices** — add `rebuild_status_indices` in `src/widgets.rs` mirroring
   `rebuild_widget_indices` (filter `m.status && !is_status_disabled`, set
   `status_indices` + `status_visible`, clamp `status_selected`). Call it
   wherever `rebuild_widget_indices` is called (`app.rs:617`, refresh paths).
3. **Prefetch + refresh** — include status-capable plugins in the prefetch set
   and the periodic refresh, mirroring the `prefetch || widget` predicate in
   `engine::execute_all`/the refresh tick (`app.rs` ~786). Refresh cadence per
   `status_refresh_secs`. Status chips read from the same `result_cache`.
4. **Layout + render** — add a chunk between content and status bar in
   `tui/ui.rs` render split: `Length(1)` when
   `status_visible && profile.allows_glance_strip()`, else `Length(0)`. New
   `render_glance_strip()`: for each `status_indices` entry, read
   `result_cache` → chip `"{icon} {status|title}"`, char-boundary-safe
   truncation, `•`-separated, dim style, focused chip highlighted
   (reverse/accent). Loading → `{icon} …`, Error → `{icon} ⚠`. Overflow →
   trailing `+N`. Add `LayoutProfile::allows_glance_strip()` in
   `tui/profile.rs` (true for Narrow/Medium/Wide, false for Phone).
5. **Focus + open** — mirror widget focus: a `status_focused` flag with ←/→
   moving `status_selected`, Enter dispatching `StatusItemOpen` which runs the
   focused plugin into `ViewOutput` exactly like the `WidgetCardOpen` handler.
   Wire the focus-entry key the same way widgets are reached
   (see `widget_actions.rs` / `widget_focused` toggles); a glance chip and a
   widget card are mutually exclusive focuses.
6. **Plugin Manager `A` picker** — extend the add/remove picker + PM view to
   show a `status` toggle column beside `widget`, persisting to
   `disabled_status`. (If the picker proves large, MVP can ship with
   config/opt-out only and add the picker toggle in the same pass.)
7. **Caffeinate** — `examples/plugins/caffeinate/manifest.toml`: `status = true`
   on the Status command (+ `status_refresh_secs`). `status.lua`: set
   `output.status = "<n>m"` (minutes remaining) on its existing path.

## Edge cases / invariants

- Strip height 0 (no layout shift) when no enabled status items.
- A plugin may be BOTH `widget` and `status` (renders in both).
- Char-boundary-safe truncation (reuse the hardened pattern) for chip text.
- Phone profile hides the strip.
- Loading/error chips are dim placeholders, never panic on missing cache.

## Out of scope (v1.x)

- Client-side ticking countdown between refreshes (chip granularity = refresh
  interval).
- Per-chip custom actions beyond "open the plugin".
- Reordering chips independently of widget order.

## Known limitations (from the 2026-05-29 adversarial review — deferred)

All require ≥2 status chips that overflow a narrow strip, or a `:layout`
override — NOT reachable with the single shipped caffeinate chip, so deferred:

- **Overflow scroll/window**: with multiple chips wider than the strip,
  h/l can move focus onto a chip collapsed into the `+N` tail (no visible
  highlight; Enter opens an off-screen plugin). v1.x: scroll the window so the
  focused chip is always rendered (render is read-only today, so this needs a
  layout pre-pass or a shared visible-count).
- **Last-chip `+N` over-reserve** + **first-chip hard-clip** on a forced-narrow
  strip — cosmetic, same multi-chip/`:layout` precondition.
- **Focus on a profile-hidden strip**: `J` on a Phone terminal (or `K` for
  widgets on Narrow) can focus an unrendered surface; recoverable via Esc/h.
  Mirrors the pre-existing widget behavior; fix both surfaces together if/when
  addressed.

Fixed in the same review pass (were reachable today): stale-index panic after
`R`/Plugin-Manager-close, auto-refresh never firing (froze the countdown — also
fixed the dormant widget auto-refresh), j/k scrolling the hidden list while the
strip was focused, and stuck focus on an emptied strip.
