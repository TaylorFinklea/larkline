# Smoke Runbook — v1.0 Phase 2 (macOS helper)

> Internal phase gate. Not a public release tag — Phase 2 lives on
> `v1.0-prep`. Run this before merging Phase 3 (Calendar v2 plugin)
> to confirm the helper baseline is stable.

## Setup

```sh
cd ~/git/larkline
git checkout v1.0-prep
cd macos-helper
swift build -c release
```

The binary lands at `macos-helper/.build/release/larkline-macos-helper`.

## Section A — Protocol smoke (no TCC required)

These don't touch EventKit, so no Calendar permission prompt fires.

```sh
cd ~/git/larkline/macos-helper
printf '%s\n' \
  '{"id":"1","command":"version"}' \
  '{"id":"2","command":"ping"}' \
  '{"id":"3","command":"nope"}' \
  'not json' \
  '' \
  | .build/release/larkline-macos-helper
```

Expected output (6 lines — empty input line is silently skipped):
```
{"helper_version":"0.1.0","kind":"hello","protocol_version":1}
{"data":{"helper_version":"0.1.0","protocol_version":1},"id":"1","ok":true}
{"data":{"pong":true},"id":"2","ok":true}
{"error":"unknown command: nope","id":"3","ok":false}
{"error":"invalid request JSON: ...","ok":false}
```

Pass criteria:
- ☐ Hello line appears first
- ☐ `version` and `ping` return `ok: true` with correct data
- ☐ Unknown command returns `ok: false` with id preserved
- ☐ Malformed JSON returns `ok: false` with id field omitted
- ☐ Empty input line emits no response (skipped)

## Section B — EventKit (TCC required)

First invocation prompts for Calendar permission. Grant it in
System Settings → Privacy & Security → Calendars if the prompt is
dismissed or doesn't fire on subsequent runs.

```sh
echo '{"id":"1","command":"list_calendars"}' \
  | .build/release/larkline-macos-helper \
  | python3 -m json.tool
```

Pass criteria:
- ☐ Returns a JSON object with `calendars` array
- ☐ Each calendar has id, title, source, allowsModifications, color
- ☐ At least one calendar from each known source (iCloud, Google, …)

```sh
# Replace dates with your current 14-day window.
echo '{"id":"1","command":"events_for_range","args":{"start_iso":"2026-05-12T00:00:00Z","end_iso":"2026-05-26T00:00:00Z"}}' \
  | .build/release/larkline-macos-helper \
  | python3 -m json.tool
```

Pass criteria:
- ☐ Returns a JSON object with `events` array
- ☐ Each event has id, title, start_iso (ISO 8601), end_iso, allDay,
  calendarId, calendarTitle, calendarSource, attendees array
- ☐ At least one event with attendees (if any work calendar synced) →
  shows mapped status (`accepted` / `needs_action` / etc.) and role
- ☐ At least one event with a meeting URL (if you have any Zoom / Teams
  / Meet events scheduled) → `meetingURL` field non-null. If you don't
  have any meetings scheduled, that's OK — the regex path isn't
  exercised but it's the same logic that mail-app-cli and
  apple-mail-mcp use in the wild.

If TCC access is denied:
```json
{"error":"calendar access denied — grant in System Settings → Privacy & Security → Calendars, then retry","id":"1","ok":false}
```

Pass: the error message is exactly that string. Calendar v2's plugin
will surface this as an error row with a help_url pointing at the
TCC settings.

## Section C — Universal binary (only when testing release artifact)

After v1.0 is tagged and CI publishes a release tarball, verify the
bundled helper:

```sh
mkdir -p /tmp/lark-smoke && cd /tmp/lark-smoke
curl -L -o lark.tar.gz \
  https://github.com/TaylorFinklea/larkline/releases/download/v1.0.0/lark-v1.0.0-aarch64-apple-darwin.tar.gz
tar xzf lark.tar.gz
ls -la lark larkline-macos-helper
file larkline-macos-helper
lipo -info larkline-macos-helper
codesign -dvv larkline-macos-helper 2>&1 | head -8
```

Pass criteria:
- ☐ Tarball contains both `lark` and `larkline-macos-helper`
- ☐ `file` reports "Mach-O universal binary with 2 architectures"
- ☐ `lipo -info` reports "x86_64 arm64"
- ☐ `codesign -dvv` reports `Signature=adhoc`

## If a scenario fails

File against `v1.0-prep`. Phase 2 sub-phases A–F live in commits
`973f922`, `8e547e7`, `8dce1b0`, `aab4904`, `be9a788` — bisect from
there. Most likely culprits by section:

- Section A fail → Protocol.swift / Commands.swift regression
- Section B fail (list_calendars) → Calendar.swift TCC path
- Section B fail (events_for_range) → Events.swift query or
  meetingURL extraction
- Section C fail → release.yml build-helper job
