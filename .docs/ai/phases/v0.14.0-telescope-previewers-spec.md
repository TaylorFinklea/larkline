# v0.14.0 — lark.nvim v4: Telescope picker previewers

## Product Overview

While scrolling rows in a Telescope results picker, render rich content for the focused row in Telescope's right-hand preview pane. Read a Jira issue body, a Confluence page, a GitHub PR description, or a Bitwarden item detail without leaving the picker. Audience: Neovim users on v0.13.0, especially Atlassian + GitHub power users for whom body text is the main read-mode value.

**Out of scope (defer to v0.14.x):** lazy preview fetching (Approach B), treesitter highlighting beyond what `filetype = "markdown"` gives for free, attachments / images, streaming previews, "open preview in main buffer" action.

## Locked Decision: Approach A (inline `preview` field)

OutputItem grows one optional field `preview: Option<String>`. Plugins populate it inline. Telescope's `define_preview` reads `entry.value.preview` and writes it synchronously.

Why A and not B (lazy fetch): cross-repo round-trip per scroll = 200ms+ latency and a fast-scroll race. Approach A is decision-complete, forward-compatible (add `preview_action` later), and ships in one PR. Why A and not C (hybrid): two code paths exceed v0.14.0's runway.

**Cost discovery — the non-trivial point.** GitHub `search/issues` already returns `body` for free (`github/my-prs.lua:54`). Atlassian list calls do NOT fetch description (`my-issues.lua:176` fields list omits it; `confluence-recent.lua:118` expand list omits `body.storage`). So:
- **GitHub PRs/issues:** zero-cost. Plumb `pr.body` → `item.preview`.
- **Atlassian Jira/Confluence:** opt-in `preview_full` plugin setting (default off). When enabled, list call adds `description` / `body.storage` and runs the existing ADF/storage reducer. When disabled, `preview` is empty.
- **Bitwarden:** `bw list items` already returns full bodies. Detail renderer in `lib.lua` is reusable.

## Interfaces and Data Flow

**OutputItem gains `preview: Option<String>`** (markdown by convention, plain text fine). Empty/missing → placeholder. Rides through `ActionWireOutcome::Chained` automatically (the variant boxes a full `PluginOutput`).

**Atlassian manifest gains one setting** `preview_full: bool` (default `false`, follows existing `[[settings]]` schema in `manifest.toml`).

**No new CLI subcommands.** No changes to `lark list --json`, `lark action`, `lark invoke`. The wire-format change is purely additive on `OutputItem`.

## Edge Cases and Failure Modes

- **Long previews (10k+ chars):** Telescope handles long buffer fills fine. Plugins should pre-truncate at ~5KB to keep the JSON payload small. Implement in the ADF/storage reducer (`lib.lua`).
- **Empty preview, present field:** treat `preview = ""` and `preview = nil` identically (placeholder).
- **Preview contains binary / control chars:** ADF/storage reducer is text-only; non-text content (Jira attachments, Confluence images) is silently skipped. Document this in the user docs.
- **Multi-byte UTF-8:** `nvim_buf_set_lines` is byte-clean. No work needed.
- **Plugin returns a chain (`ActionResult::Chained(output)`):** the chained `PluginOutput`'s items inherit `preview` support automatically — no extra plumbing.
- **Forms / mini-apps fall back:** `fallback.needs_fallback(output)` already short-circuits the picker. Previewer never runs in that path. No interaction.
- **Preview pane disabled by user (Telescope theme = `dropdown`):** previewer is silently ignored. Picker still works. Document in user docs.
- **Race on fast scroll:** with synchronous fill and in-memory data, no race possible. Each `define_preview` call completes before the next one fires.
- **Atlassian `preview_full` off:** preview is empty for those plugins; pane shows the placeholder. This is the expected/default UX, not a bug.
- **Bitwarden vault locked:** items list returns the "not unlocked" sentinel row; preview is empty; pane shows placeholder. Consistent with v0.11.0 lock-state UX.
- **GitHub PR body == null** (rare; PRs without descriptions): `pr.body` is JSON null, decodes to Lua `nil`, `preview = nil`. Placeholder shows. Correct.

## Risks

| Risk | Mitigation |
|---|---|
| Telescope's `define_preview` requires `vim.schedule` wrap and our sync fill flickers | Investigate during Phase B; if needed, wrap. Cost: 3 lines. |
| Atlassian `preview_full=true` adds noticeable list-call latency | Default off. Document tradeoff in plugin docs. |
| Confluence storage-format reducer is too lossy / shows raw HTML | Storage format is XHTML-ish; one regex pass strips tags. If quality is poor, defer Confluence preview to v0.14.x and ship Jira-only. |
| Bitwarden preview leaks data on screenshare | Match existing TUI detail-view redaction (already redacts password/TOTP/hidden fields). Document in user docs. |
| `cargo test` smoke test starts asserting on `preview` shape | Phase A test is purely additive; existing assertions ignore unknown fields. |
| 5KB preview truncation cuts mid-codeblock | Truncation point: end of last paragraph before 5KB. Acceptable for read mode. |
