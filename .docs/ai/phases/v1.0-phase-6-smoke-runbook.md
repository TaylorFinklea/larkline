# Phase 6 — AI Single-Shot — Smoke Runbook

> Manual end-to-end verification for Phase 6 against ≥1 real provider.
> Run from your machine before tagging Phase 6 ✅ in `current-state.md`.

## Prerequisites

- One of: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `OPENROUTER_API_KEY`,
  or a running local Ollama server.
- `~/.config/larkline/config.toml` exists (the TUI creates it on first
  launch; CLI subcommand creates it too if absent).

## A — CLI single-shot (3 minutes)

The CLI is the canonical entry point; if this passes the plugin path is
99% likely to work too.

### A.1 — Help renders

```sh
lark ai-ask --help
```

**Expect:** four-line help with `--system / --model / --max-tokens` flags.

### A.2 — No args is a usage error

```sh
lark ai-ask
echo $?
```

**Expect:** non-zero exit; `Error: Usage: lark ai-ask [OPTIONS] <PROMPT...>` on stderr.

### A.3 — Missing key surfaces a friendly Auth error

```sh
unset ANTHROPIC_API_KEY  # if currently set in this shell
# Edit ~/.config/larkline/config.toml: [ai] provider = "anthropic"
lark ai-ask "hello"
```

**Expect:** non-zero exit; stderr says `ANTHROPIC_API_KEY is not set
(run lark secret set ANTHROPIC_API_KEY or export it)`.

### A.4 — Happy-path streaming

Pick the provider with a valid key set:

```sh
# Anthropic — recommended path
lark secret set ANTHROPIC_API_KEY    # one-time; stores in Keychain
# Edit ~/.config/larkline/config.toml: [ai] provider = "anthropic"
lark ai-ask "what does Larkline do, in 20 words"

# OR OpenAI
lark secret set OPENAI_API_KEY
# Edit config: [ai] provider = "openai"
lark ai-ask "what does Larkline do, in 20 words"

# OR OpenRouter
lark secret set OPENROUTER_API_KEY
# Edit config: [ai] provider = "openrouter"
lark ai-ask "what does Larkline do, in 20 words"

# OR Ollama (local — needs `ollama serve` running with a model pulled)
ollama pull llama3.2
# Edit config: [ai] provider = "ollama"
lark ai-ask "what does Larkline do, in 20 words"
```

**Expect:**
- Text streams in real-time (you should *see* the response materialize,
  not arrive all at once).
- Final newline.
- One stderr line: `[tokens in=N out=N]` (skipped for Ollama, which
  doesn't always emit usage).

### A.5 — System prompt + model override

```sh
lark ai-ask --system "Always answer in pirate dialect." "what time is it"
lark ai-ask --model claude-haiku-4-5 "two plus two"  # anthropic
lark ai-ask --max-tokens 32 "describe quantum physics"  # truncates
```

**Expect:** `--system` visibly affects tone; `--model` switches to the
named model (verify with a model that responds differently); `--max-tokens`
truncates and stderr shows `[stop_reason=MaxTokens]` (or similar).

## B — TUI plugin (5 minutes)

### B.1 — Plugin discovers

```sh
# If examples/plugins/ai/ isn't symlinked into your plugin dir yet:
ln -s "$(pwd)/examples/plugins/ai" "$HOME/.config/larkline/plugins/ai"

lark list | grep -i "ai ask"
```

**Expect:** one line for `AI Ask`.

### B.2 — Form appears on first run

Launch `lark`, search "AI Ask", press Enter.

**Expect:**
- Form with two fields: `Prompt` (required, placeholder "What do you
  want to ask?") + `System prompt (optional)`.
- Submit button labeled `Ask`.

### B.3 — Empty submit is rejected gracefully

Press Enter on empty prompt field.

**Expect:** Row labeled "No prompt provided" with detail "Submit a
prompt to ask the AI". No crash, no stderr noise.

### B.4 — Happy-path render

Type a prompt like "list 3 productivity tools" and submit.

**Expect:**
- Row 1: label = your prompt, icon = 🤖, detail = full response
  (visible in preview pane).
- Row 2: label = "Tokens: N in / M out", icon = 📊 (if the provider
  reported usage — Anthropic/OpenAI always do; Ollama doesn't).
- `c` or Cmd-C copies the full response to clipboard.

### B.5 — Error rendering

Set an invalid model in config (e.g. `model = "not-a-real-model"`),
restart `lark`, ask anything.

**Expect:**
- One row with ❌ icon, label = "AI request failed", detail = stderr.
- Status bar shows `[o] help` hint.
- Pressing `o` opens
  <https://github.com/TaylorFinklea/larkline/blob/main/docs/AI_INTEGRATION.md>
  in the browser.

### B.6 — Friendly label for missing-key error

Remove your API key (in Keychain + env), keep the provider configured,
ask anything.

**Expect:** Label is "AI provider key missing" (not the raw stderr);
detail mentions `lark secret set <KEY>`; help URL points to
AI_INTEGRATION.md.

## C — Cross-checks

```sh
cd "$(git rev-parse --show-toplevel)"

```

**Expect:** `test result: ok. 210 passed`.

### C.2 — Clippy clean

```sh
cargo clippy --bin lark -- -D warnings
```

**Expect:** no output, no errors.

### C.3 — Plugin manifest validates

```sh
cargo test --test plugin_manifest_integration_test
```

**Expect:** `test result: ok. 1 passed`.

## Pass criteria

- A.1, A.2, A.3, A.4 all pass for at least one provider.
- B.1, B.2, B.3, B.4, B.5 all pass.
- C.1, C.2, C.3 all pass.

A.5 + B.6 are recommended but not required to ship Phase 6 — they're
polish.

## Known gaps (deferred)

- **No streaming UX inside the TUI plugin.** The CLI streams; the
  plugin blocks on `lark.exec_io`. Phase 6.5 adds an in-Lua streaming
  primitive (likely `lark.ai_ask(prompt, on_delta)` taking a Lua
  callback).
- **No Re-ask action.** Each AI Ask invocation re-shows the form.
  Chain-action re-ask is a v1.x nice-to-have.
- **Ollama tool-capable models only.** Phase 6 doesn't pass tools, so
  not relevant here — surfaces in Phase 8.

If any check fails, file a v1.0 bug and pause before tagging.
