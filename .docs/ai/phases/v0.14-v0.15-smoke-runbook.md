# Smoke Runbook — v0.14.0 + v0.15.0

> Manual gate Taylor walks through before tagging. Both releases ship together
> on the same nvim+Telescope build session. v0.14.0 covers Telescope previewers;
> v0.15.0 covers plugin error UX (`[o] help` hints + `help_url` open).

## Setup (one-time)

```sh
cd ~/git/larkline
git checkout v0.15.0-prep   # contains v0.14.0 + v0.15.0 + MIT relicense
cargo build --release
cd ~/git/lark.nvim
git checkout v0.14.0-prep   # contains v0.14.0 previewer
```

In your nvim config (`~/git/chezmoi-config/dot_config/nvim/lua/plugins/lark.lua`)
the `dir = ~/git/lark.nvim` already picks up `v0.14.0-prep`. Open nvim with the
freshly-built binary on PATH:

```sh
LARK_BINARY=~/git/larkline/target/release/lark nvim
```

## Section A — v0.14.0 Telescope Previewers

`:Telescope lark`, then **hover** rows (no Enter — the previewer fires on selection).

1. **GitHub PR body** — open `My Pull Requests`, hover any row → right pane shows the PR body as markdown. Empty body → placeholder, no crash.
2. **Atlassian Jira `preview_full=true`** — set `preview_full = "true"` in the Atlassian plugin settings, then open Jira issues, hover a row → description renders. Toggle off → placeholder.
3. **Confluence quality check** — same toggle, open a Confluence page picker, hover. Prose-heavy pages should look fine; macro-heavy pages may show stripped-tag debris. **Tell the agent if quality is unacceptable** — Confluence may need to gate behind a separate setting.
4. **Bitwarden redacted preview** — hover a vault login row → detail markdown renders, password masked. Hover a Secure Note → body renders.
5. **Fallback paths** — pick a form action (Bitwarden "Generate Password") → floating terminal. Pick a mini-app (Docker Dashboard) → mini-app launches. Confirms additive `preview` field didn't break form/chain/mini-app flows.

## Section B — v0.15.0 Error UX

For each plugin you use, **trigger a known failure** and verify the error row.

What to confirm on every failure:
- Row icon is `!`
- Status bar shows `[o] help` (it should NOT show `[r] retry` — no plugin sets `retry_action` in v0.15.0)
- Pressing `o` opens the right docs URL in your browser
- Pressing `r` re-runs the plugin (existing behavior preserved)

Failure recipes:

| Plugin | Trigger | Expected help URL |
|---|---|---|
| GitHub | `unset GITHUB_TOKEN` | docs.github.com/.../personal-access-tokens |
| GitHub | bogus token (HTTP 401) | docs.github.com/en/authentication |
| Atlassian | `unset ATLASSIAN_API_TOKEN` | manage-profile/security/api-tokens |
| Atlassian | bogus host | status.atlassian.com |
| Bitwarden | `bw lock` then run a Bitwarden command | bitwarden.com/help/cli/#using-the-cli |
| Linear | `unset LINEAR_API_KEY` | linear.app/docs/api-and-webhooks |
| Docker | stop Docker Desktop, run any docker plugin | docs.docker.com/config/daemon/start |
| k8s | `kubectl config delete-context ...` to clear context | kubernetes.io/docs/.../kubeconfig |
| HA | `unset HA_TOKEN` | home-assistant.io/docs/authentication |

You don't need all 8 — **GitHub, Atlassian, Bitwarden, Docker** are the ones you
use daily; 1–2 failure paths each is enough to validate the contract. If the
first 2 plugins behave correctly, the rest follow the same pattern.

## Tag sequence (only after all green)

```sh
bash scripts/release.sh set 0.14.0     # in larkline (v0.14.0-prep gets tagged)
git -C ~/git/lark.nvim tag v0.14.0 && git -C ~/git/lark.nvim push --tags
bash scripts/release.sh set 0.15.0     # in larkline (v0.15.0-prep gets tagged)
```

If a scenario fails: file the symptom against the matching `-prep` branch; fix
on that branch; re-test only the failing scenario; tag.
